# 本地 Prompt 检索插件设计方案

> 当前实现：`c 文本` 直接保存输入内容，只输入 `c` 时才保存剪贴板；`v` 检索已有模板，`pt` 作为 `v` 的别名。下文仍保留第一版 `pt` 方案原文。

## 1. 目标

设计一个 Creta 插件，让用户在搜索框中输入关键字后，能够快速检索本地预设的 Prompt 模板，并一键复制到剪贴板，随后直接粘贴到 ChatGPT、Claude、Gemini、通义千问等 AI 平台中使用。

这个插件的核心价值是：

- 把常用 Prompt 模板集中管理在本地
- 用统一入口快速搜索
- 减少手动打开文档、复制粘贴的步骤
- 让高频 Prompt 可以像启动应用一样被快速调用

## 2. 典型使用场景

### 场景 1：快速调用写作模板

用户打开 Creta，输入：

```text
pt 写周报
```

搜索结果显示：

- 写周报助手
- 周报润色模板
- 周报总结模板

用户选中“写周报助手”并回车后，插件直接将完整 Prompt 复制到剪贴板。

### 场景 2：按标签查找 Prompt

用户输入：

```text
pt 翻译 英文
```

插件根据标题、关键词、标签进行匹配，返回与“翻译”“英文”相关的模板。

### 场景 3：复制后立即粘贴

用户在 AI 平台输入框中直接 `Ctrl + V`，即可粘贴刚刚复制的 Prompt。

## 3. 推荐交互方式

建议为插件定义独立动作关键字：

```text
pt
```

这样用户的使用方式统一为：

```text
pt 关键词
```

示例：

- `pt 总结`
- `pt 翻译`
- `pt SQL`
- `pt 面试`

也可以考虑备选关键字：

- `prompt`
- `ai`
- `tpl`

但从输入效率看，`pt` 更短、更适合高频使用。

## 4. MVP 功能范围

第一版建议只做最重要的能力，避免一开始做得太重。

### 4.1 必须功能

- 支持本地 Prompt 模板存储
- 支持按标题、关键词、标签搜索
- 支持搜索结果排序
- 支持选中后复制完整 Prompt 到剪贴板
- 支持在结果列表中预览简短描述
- 支持插件设置中配置模板文件路径

### 4.2 建议功能

- 支持重新加载模板
- 支持最近使用记录
- 支持置顶常用 Prompt
- 支持模板分类显示

### 4.3 后续增强功能

- 支持变量占位符，例如 `{topic}`、`{language}`
- 支持复制前填写参数
- 支持多行预览
- 支持导入导出模板
- 支持 Markdown 或 YAML 模板格式
- 支持收藏和统计使用次数

## 5. 用户流程设计

### 5.1 主流程

1. 用户按 `Alt + Space` 打开 Creta
2. 输入 `pt 关键词`
3. 插件从本地模板库中搜索匹配项
4. Creta 展示匹配结果
5. 用户按回车
6. 插件将模板正文复制到系统剪贴板
7. 用户切换到 AI 平台粘贴使用

### 5.2 无搜索词时

当用户只输入：

```text
pt
```

建议展示：

- 最近使用的 Prompt
- 置顶 Prompt
- 常用分类入口
- 使用说明，例如“输入关键字搜索本地 Prompt”

### 5.3 复制后的反馈

复制成功后建议给出轻量反馈，例如：

- 标题：`已复制 Prompt`
- 内容：`“周报总结模板” 已复制到剪贴板`

这样用户能明确知道操作已成功。

## 6. 本地数据结构设计

建议第一版使用 `JSON` 文件作为本地模板库，原因是：

- 简单直接
- 易于解析
- 便于用户手动编辑
- 跨语言实现都方便

### 6.1 推荐文件名

```text
prompts.json
```

### 6.2 推荐数据结构

```json
[
  {
    "id": "weekly-report",
    "title": "周报总结模板",
    "description": "用于整理本周工作并生成周报",
    "tags": ["总结", "周报", "工作"],
    "keywords": ["周报", "汇报", "工作总结"],
    "content": "请根据以下工作内容，帮我整理一份结构清晰、表达专业的周报：",
    "category": "办公",
    "favorite": true
  },
  {
    "id": "translate-en-zh",
    "title": "英文翻译成中文",
    "description": "将英文内容翻译为自然、准确的中文",
    "tags": ["翻译", "英文", "中文"],
    "keywords": ["翻译", "英译中", "英文"],
    "content": "请将下面的英文内容翻译成自然、准确、符合中文表达习惯的中文：",
    "category": "翻译",
    "favorite": false
  }
]
```

### 6.3 字段说明

- `id`：模板唯一标识
- `title`：模板名称，搜索权重最高
- `description`：简短说明，用于结果列表展示
- `tags`：标签数组
- `keywords`：补充检索词
- `content`：复制到剪贴板的完整 Prompt 内容
- `category`：分类
- `favorite`：是否收藏或置顶

## 7. 检索逻辑设计

### 7.1 检索范围

建议同时搜索以下字段：

- `title`
- `tags`
- `keywords`
- `description`

### 7.2 排序规则

建议按以下优先级排序：

1. 标题完全匹配
2. 标题前缀匹配
3. 关键词匹配
4. 标签匹配
5. 描述匹配
6. 收藏项加权
7. 最近使用项加权

### 7.3 模糊搜索

建议支持模糊匹配，而不是只做完全匹配。  
例如用户输入：

```text
pt 周报
```

即使模板标题叫“每周工作总结模板”，也应该尽量能搜出来。

### 7.4 中文搜索优化

如果后续要进一步提升体验，可以增加：

- 拼音搜索
- 首字母搜索
- 同义词映射

但这部分可以放到第二阶段。

## 8. 搜索结果展示设计

每条结果建议展示以下信息：

- 主标题：Prompt 名称
- 副标题：简短描述或分类
- 图标：统一 Prompt 图标

示例：

```text
周报总结模板
用于整理本周工作并生成周报 · 办公
```

### 8.1 回车行为

按 `Enter` 后：

- 复制 `content` 到剪贴板
- 显示“已复制”提示
- 可选择是否自动隐藏主窗口

### 8.2 上下文菜单建议

可以通过 `Shift + Enter` 打开上下文菜单，支持：

- 复制 Prompt
- 复制标题
- 打开模板文件
- 重新加载模板
- 标记为收藏

## 9. 技术实现建议

## 9.1 推荐实现路线

推荐优先使用 `C#` 插件实现，原因是：

- 与 Creta 主项目技术栈一致
- 本地文件读取和剪贴板操作更直接
- 启动速度和集成体验更稳定
- 后续做设置面板更方便

如果目标是“先快速验证功能”，也可以先做 `Python` 或 `Node.js` 版本原型。

### 9.2 建议插件命名

- 插件名：`Local Prompt Search`
- 动作关键字：`pt`
- 插件目录示例：

```text
Plugins/Creta.Plugin.BrowserBookmark
```

### 9.3 核心模块划分

- `PromptRepository`
  - 负责读取本地 JSON 文件
  - 负责缓存模板数据

- `PromptSearchService`
  - 负责关键词匹配
  - 负责结果评分与排序

- `ClipboardService`
  - 负责复制内容到剪贴板

- `Settings`
  - 保存模板文件路径
  - 保存是否启用最近使用、收藏等选项

- `Main`
  - 接收 Creta 查询
  - 返回结果列表
  - 处理回车动作

## 10. 插件工作流程

### 10.1 初始化阶段

插件启动时：

1. 读取配置
2. 定位 `prompts.json`
3. 加载模板到内存
4. 建立搜索索引

### 10.2 查询阶段

用户输入：

```text
pt 翻译
```

插件执行：

1. 截取搜索词 `翻译`
2. 遍历模板数据
3. 计算匹配分数
4. 按分数排序
5. 返回结果列表

### 10.3 执行阶段

用户按回车后：

1. 获取对应模板的 `content`
2. 复制到剪贴板
3. 记录最近使用
4. 显示成功提示

## 11. 配置设计建议

建议在插件设置页支持以下配置：

- 模板文件路径
- 默认动作关键字
- 是否显示最近使用
- 是否显示收藏优先
- 复制后是否自动隐藏窗口
- 启动时是否自动加载模板

### 11.1 默认路径建议

可以提供一个默认模板库路径，例如：

```text
%APPDATA%/Creta/Plugins/LocalPromptSearch/prompts.json
```

或者：

```text
Documents/FlowPrompts/prompts.json
```

如果文件不存在，插件可自动生成一个示例文件。

## 12. 异常处理设计

为了让非技术用户也能顺利使用，建议处理以下异常：

- 模板文件不存在
- JSON 格式错误
- 模板字段缺失
- 剪贴板写入失败
- 文件编码异常

建议在结果页或弹窗中给出明确提示，例如：

- `未找到 prompts.json，请先配置模板文件路径`
- `模板文件格式错误，请检查 JSON 内容`

## 13. 性能建议

Prompt 模板通常数量不会特别大，第一版直接加载到内存即可。

建议：

- 启动时一次性读取模板
- 查询时只在内存中搜索
- 文件变更后支持手动或自动刷新

如果后续模板数量很多，再考虑：

- 建立缓存索引
- 增量更新
- 拼音索引

## 14. 安全与隐私

因为这是本地 Prompt 检索插件，建议坚持以下原则：

- 默认不联网
- 模板数据仅保存在本地
- 不上传用户 Prompt
- 不采集用户输入内容

这对涉及公司内部知识、业务流程、敏感表达模板的场景尤其重要。

## 15. 分阶段实施建议

### 第一阶段：最小可用版本

- `pt` 关键字触发
- 本地 JSON 模板加载
- 标题/标签/关键词搜索
- 回车复制到剪贴板
- 成功提示

### 第二阶段：可用性增强

- 最近使用
- 收藏置顶
- 设置面板
- 重载模板
- 更好的排序逻辑

### 第三阶段：高级能力

- 占位符变量
- 表单输入参数
- 分类筛选
- 多文件模板库
- 导入导出

## 16. 推荐的第一版结论

如果以“尽快做出好用版本”为目标，建议第一版采用下面这套组合：

- 插件关键字：`pt`
- 本地模板格式：`JSON`
- 实现语言：`C#`
- 核心动作：搜索 + 回车复制
- 排序策略：标题优先，标签和关键词辅助
- 默认能力：收藏、最近使用可先不做复杂界面，只保留数据字段

这样可以最快落地，而且足够解决“本地 Prompt 快速检索并复制”的核心需求。

## 17. 一句话总结

这个插件本质上是一个“本地 Prompt 快捷启动器”：  
用户输入 `pt + 关键词`，插件从本地模板库中找到最合适的 Prompt，并一键复制到剪贴板，方便立即粘贴到 AI 工具中使用。
